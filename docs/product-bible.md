# 12 Circle — Product Bible

The single source of truth for **how the product should behave and why**. Not a
technical spec (see `movement-intelligence-engine.md` for that) — this is the
product's constitution. When a decision is ambiguous, this document wins.

> If you are adding a feature and it violates a principle or AI rule below,
> the feature is wrong — not the rule. Escalate before shipping it.

---

## 1. Vision

12 Circle is a **coaching operating system**, not a workout app. It exists to
make expert coaching **scalable, consistent, and explainable** — amplifying great
coaches rather than replacing them, and giving self-guided clients a system that
reasons like a coach instead of shuffling a static template.

The differentiator is a **deterministic coaching engine** that plans, generates,
adapts, and predicts — with AI layered on top purely to *communicate*. Every
recommendation can answer "why?" with a real, recorded reason.

## 2. Product Philosophy

These are load-bearing. They are why the architecture looks the way it does.

1. **The engine decides. AI explains.** All programming, scoring, adaptation, and
   prediction is deterministic. The LLM never makes a coaching decision.
2. **Every recommendation is explainable.** Nothing reaches a user without a
   recorded decision trace it can be justified from.
3. **Coaches stay in control.** For coach-guided clients, the coach approves
   changes that matter. The system proposes; the coach disposes.
4. **Knowledge is reviewed before it becomes production truth.** AI-drafted
   content and exercise intelligence flow through a human review pipeline
   (per-attribute) before the engine consumes them.
5. **Human expertise is amplified, not replaced.** The Copilot saves a coach time;
   it never removes their judgment from the relationship.
6. **Completed history is immutable.** The system adapts the future, never rewrites
   what already happened.
7. **Deterministic first, delightful second — but always both.** Correctness is
   non-negotiable; so is a product coaches enjoy using.

## 3. Coaching Principles

- **A great coach individualizes.** Recommendations must reflect the client's
  goal, recovery, experience, equipment, and injuries — never a generic plan.
- **A great coach is consistent.** The same inputs produce the same, defensible
  decision every time (this is why the engine is deterministic).
- **A great coach protects the client.** Injury signals and low recovery override
  progression. Safety beats overload.
- **A great coach explains.** The client should understand *why* today looks the
  way it does, in plain language.
- **AI behaves like a thoughtful assistant coach:** it drafts, summarizes,
  encourages, and flags — then steps back for the human on anything consequential.
- **AI defers to the coach** on: goal changes, injury adaptations, and any change
  the approval matrix marks as requiring sign-off for that coaching mode.

## 4. Design Principles

- **Show the grounding.** Where the AI speaks, the deterministic facts it spoke
  from should be visible (e.g. the Weekly Review shows the brief; the Copilot
  shows the decision trace). Trust comes from transparency.
- **Coach-in-control UX.** Consequential actions are proposed with a clear
  Approve / Edit / Reject, never auto-committed silently for coach-guided clients.
- **Calm, premium, focused.** Dark layered black-purple theme; one primary action
  per screen; progressive disclosure over dense dashboards.
- **Every state is designed:** loading (engine calls take a beat), empty (no
  clients / no content / no feedback), error (name the failure, offer the retry),
  and success (celebrate meaningfully).
- **Consistency across surfaces.** The coach tools (Copilot, Program Builder,
  Continuous Coaching, Weekly Review, Content Center) share layout, color, and
  interaction grammar.
- **Accessibility is a requirement, not a polish item.** Contrast, tap targets,
  and legible type from the start.
- **Degrade gracefully.** If an engine/migration/secret isn't live, show the
  useful subset and say what's missing — never a blank screen or a crash.

## 5. Terminology (use these words, consistently)

| Term | Meaning |
|------|---------|
| **Program** | A multi-week plan (mesocycles → weeks → days) generated by the Program Intelligence Engine. |
| **Workout / Session** | One day's set of exercises within a program. "Session" is the client-facing word. |
| **Mesocycle** | A training phase (e.g. Foundation, Progressive Overload, Intensification, Deload). |
| **Recovery** | The client's reported/observed recovery state (0–100). |
| **Readiness** | Recovery + energy + sleep synthesized into "how prepared to train." |
| **Confidence** | 0–100, how sure a *prediction* is (goal completion, outcome). Never a coaching decision's confidence. |
| **Intelligence** | Structured programming metadata on an exercise (fatigue, joint stress, goal fit, etc.). |
| **Certification** | Which platform modules an exercise is cleared to be used by (Workout Builder, AI Coach, …). |
| **Decision Trace** | The recorded, deterministic reasoning behind a generated workout or regeneration. |
| **Brief** | The deterministic grounding packet a communication is written from. |
| **Coaching Mode** | free · self-guided · ai-guided · coach-guided. Gates features and approval rules. |
| **Regeneration** | Adapting *future* weeks of a program from weekly feedback (never past weeks). |

Avoid: "AI generated your program" (the *engine* did), "the AI thinks" (it
explains, it doesn't think), "smart" as a feature name.

## 6. AI Rules (hard constraints — enforced in code, not just prose)

**AI may:**
- Explain a decision, prediction, or program change — using only its trace/brief.
- Summarize what happened (weekly/daily/monthly).
- Encourage and personalize the *tone* of communication.
- Draft content and exercise intelligence **for human review**.

**AI may NOT:**
- Invent or alter programming, sets/reps, or progression.
- Override or contradict a deterministic rule, score, or decision trace.
- Recommend exercises outside **certified** knowledge.
- Fabricate metrics, dates, or reasons not present in the grounding data.
- Bypass the coach approval matrix for coach-guided clients.
- Make a claim it cannot ground; if data is missing, it says so.

**Enforcement:** these are implemented as constrained edge functions
(`explain-decision`, `generate-communication`) whose prompts and input assembly
restrict the model to recorded traces/briefs, plus RLS and approval RPCs. A new
AI feature must route through this pattern — deterministic input → grounded
translation → (coach approval where required) → surface.

## 7. What we are deliberately NOT building (pre-beta)

New foundational engines, new backend subsystems, new migrations for their own
sake. The foundation is complete. Remaining "features" (Daily Brief, Celebration
Engine, Goal/Prediction dashboards, Client Timeline) are **presentation layers
over existing engines**. See `beta-readiness.md`.

## 8. The next milestone

Not another feature. **The first private beta** with real coaches using the
platform daily — after Section 0 of the Beta Readiness Checklist is executed and
the exercise library is substantially populated. Learning from real usage
outranks any additional intelligence we could add.
