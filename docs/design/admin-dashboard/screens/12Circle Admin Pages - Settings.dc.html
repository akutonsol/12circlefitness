Settings detail pattern

Every settings page

  1. Header — name, description, who it applies to (Personal · Administrator · Organization · Platform)
  2. Status — current state and last change, who made it, link to its audit history
  3. Configuration — grouped fields, never one long form
  4. Actions — the unsaved-changes bar appears only after an edit: Discard, Save
  5. Audit — before, after, who, when, reason, in Trust → Audit logs; Settings keeps no audit of its own

Responsive behaviour

Tablet · 768–1199 px

  • Settings nav collapses to a category picker above the page
  • Two-column field groups stack
  • Tables keep name and status; the rest opens in a drawer

Small screens · under 768 px

  • Each category is its own screen with a back link
  • Field groups become expandable sections
  • The unsaved-changes bar pins to the bottom of the screen
  • Confirmations open as full-screen sheets
